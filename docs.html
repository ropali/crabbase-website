Getting Started with Crabbase

This guide gets Crabbase running locally so you can use it as a ready-made backend — no custom REST code required. The only required external service is a PostgreSQL server (yours): everything else — API, admin dashboard, migrations — ships inside the single binary.

info

Evolving project: flag names, defaults, and response shapes may change between versions. The Swagger UI (GET /api/docs) and OpenAPI spec (GET /api/openapi.json) are available in debug builds only; release builds exclude them.

Installation

Build it from source and launch it through Make or Cargo, or build the dashboard assets once for a fresh checkout.

Prerequisites: Rust stable, PostgreSQL 14+ (local or reachable), and Trunk with the wasm32-unknown-unknown target for the dashboard. psql is optional.

From the repository root. The admin command serves the dashboard and API together; serve exposes the API only.

BASH 
# 1. Configure your Postgres connection
cp example.crabbase.toml crabbase.toml

# 2. Build the dashboard assets once (fresh checkout)
cd crates/admin-ui && trunk build && cd ../..

# 3. Start the dashboard + API on :9898
make admin

Run either subcommand directly through Cargo. Both read the same TOML file and run migrations before listening.

BASH 
# API only on :8989
cargo run -- serve --config crabbase.toml

# Dashboard + API on :9898
cargo run -- admin --config crabbase.toml

The dashboard's compiled JS/WASM assets are build artifacts. A fresh checkout must build them once with Trunk and the wasm32-unknown-unknown target.

BASH 
# One-time target + dashboard build
rustup target add wasm32-unknown-unknown
cd crates/admin-ui && trunk build

# Production: dashboard + release binary
make release

Configure Crabbase

Crabbase reads a TOML file — crabbase.toml by default. Pass --config <path> to either subcommand to use a different file.

crabbase.toml 
[database]
host = "localhost"
port = 5432
user = "postgres"
password = "postgres"   # prefix with $ to load from env, e.g. $DB_PASSWORD
database = "crabbase"
schema = "crabbase"
max_connections = 10

[server]
host = "0.0.0.0"
port = 8989

[admin]
host = "0.0.0.0"
port = 9898

# Superusers to create if missing on first boot (array of tables)
[[initial_users]]
email = "admin@crabbase.local"
name = "admin"
password = "admin123"   # or $ADMIN_PASSWORD to pull from env
Section Purpose
[database] PostgreSQL host, port, credentials, database, schema, and pool size.
[server] Public API bind address and port. Defaults to 0.0.0.0:8989.
[admin] Dashboard + admin API bind address and port. Defaults to 0.0.0.0:9898.
[[initial_users]] Superusers created if missing on first boot. Existing emails are left untouched.

Passwords may reference environment variables: a value starting with $ is read at startup, e.g. password = "$DB_PASSWORD". There are no --host/--port flags; edit the TOML sections instead. max_connections is parsed but not yet applied to the pool.

Running Crabbase

Two commands cover every deployment shape. Both share the same database and run the same boot sequence. You can run both at once; in practice admin alone gives you everything.

dns crabbase serve

The REST API under /api. Ideal for public-facing instances behind your load balancer.

http://0.0.0.0:8989
dashboard crabbase admin

The REST API plus the embedded admin dashboard SPA at /.

http://0.0.0.0:9898

What happens on boot

  1. 1 Logging initializes — pretty console logs filtered by RUST_LOG, plus daily-rotating JSON logs in logs/app.log.
  2. 2 The TOML config is loaded.
  3. 3 A connection pool is created and connectivity is verified with SELECT 1.
  4. 4 Embedded SQL migrations run automatically — no external migration step.
  5. 5 Any missing [[initial_users]] superusers are created.
  6. 6 The startup banner is printed.

Your first steps

From zero to a live REST endpoint in four steps.

1

Open the dashboard

Go to http://localhost:9898 and log in with the email/password from [[initial_users]].

2

Create a collection

Use the Create Collection drawer to make a posts collection with a few fields.

3

Set your API rules

Collections start private. In the Edit Schema drawer, set List/View to Everyone (public) for unauthenticated reads.

4

Query the API

Your endpoint is live immediately. In a debug build, explore it interactively at http://localhost:9898/api/docs.

BASH 
curl http://localhost:8989/api/collections/posts/records

Troubleshooting

The most common startup and connection issues, and how to fix them.

Symptom Fix
Config file not found / invalid TOMLCheck the path passed to --config and the [database], [server], and [admin] sections.
env variable ... not setA $VAR reference in a password field points at an unset environment variable.
Cannot connect to PostgresVerify the [database] host/port/user/password/database and that the server is running.
Port already in useChange [server].port or [admin].port in crabbase.toml.
Dashboard is blank / assets 404Build the dashboard with cd crates/admin-ui && trunk build (or make release).
/api/docs returns 404Swagger/OpenAPI are excluded from release builds; run a debug build.
Login failsUse the email/password configured in [[initial_users]] (or the environment variable it references); editing that file does not update an account created earlier.
Built-in UI Accessing the Web Dashboard

Whenever you run crabbase admin, the administrative interface is reachable by default at http://localhost:9898. It logs in against the same _superusers endpoint as the API.
